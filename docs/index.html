LC-3 virtual machine and two-pass assembler. Header-only, C++20. Reference for the public API only, not an implementation walkthrough.

github.com/0xbad4/lc3kit header-only, CMake install see LICENCE.md
Namespace collision. lc3kit::vm and lc3kit::lasm both define an error_type and an err_str(). If both headers are included, qualify the namespace explicitly (vm::error_type, lasm::error_type) or the wrong one will resolve silently.

// why this exists

  • Low level practice. Build something outside interpreted languages, close to the hardware.
  • Machine level. Work through instruction fetch/decode/execute, registers, and memory as an actual model instead of reading about it.
  • Assemblers and compilers. See how source text becomes symbol tables and encoded machine words, stage by stage.
  • Base for LC3kit-IDE. This library is the engine underneath a second project, a debugger and teaching tool for students learning the LC-3 architecture.

lc3kit::vm::VM is a full LC-3 instruction set simulator, plus an optional lc3kit-ext opcode extension (SHL, SHR, MUL, DIV). It exposes a hook system so a debugger, IDE, or test harness can observe every memory access, register write, trap, and interrupt without touching the execution loop itself. Everything below lives in lc3kit/lc3vm/vm.h, included as #include <lc3kit/vm>. 

// minimal run loop
lc3kit::vm::VM vm;
vm.load(obj_stream);
auto err = vm.run();

if (!vm.ok()) {
    // vm.get_last_error() / err_str(err)
}

hooks (vm_hooks)

A plain struct of std::function fields, all nullptr by default, from lc3vm/hooks.h. Reach it through vm.hooks() and assign only what you need. Every callback receives a VM& as its first argument.

hookfires
on_start / on_resetstart of run() (unless resuming from a breakpoint) / inside reset()
before_instruction / after_instructionaround each fetch-decode-execute cycle, with the current PC
before_memory_read / after_memory_readaround mem_read(), when hk is true
before_memory_write / after_memory_writearound mem_write(), when hk is true
before_register_write / after_register_writearound a general-purpose register write
on_breakpointPC lands on a set breakpoint; return value decides what happens next (see note below)
before_trap / after_traparound TRAP servicing, with the 8-bit vector
before_interrupt / after_interruptaround interrupt servicing
on_invalid_instructionan illegal opcode is fetched
on_invalid_memory_accessuser mode tries to touch supervisor space or device registers
on_haltexecution stops, with the PC and whether the stop was forced
on_breakpoint returns a bool: true means keep running, false means pause. There is no separate resume(). To continue after a pause, call run() again, it detects the paused-on-breakpoint state and continues from there.

control and execution

methodreturnsdescription

add_break_point(addr)void

~VM()-Frees memory/register storage, fires on_halt if still running.
Multiple .ORIG images. load() reads exactly one image per call. A program with several .ORIG blocks needs one load() call per block, and PC is reset to the origin of whichever image was loaded last.
JSR / JSRR / RET. JSR and JSRR write R7 directly and do not fire the register-write hooks or touch condition codes. RET has no separate code path, it is JMP R7 by convention, so it goes through the same handling as JMP.
MCR write side effect. Writing to the MCR address with bit 15 cleared halts the VM immediately from inside mem_write(), regardless of whether the write came from simulated code or a direct host call.
GETC / IN busy-wait. Both traps spin on the keyboard ready bit inside the trap handler. If nothing external ever sets KBSR, the trap does not return.
Interrupts. Only one interrupt source is modeled: interrupts::KEYBOARD. There is no general interrupt vector table beyond that.

lc3kit::lasm::Asm is the orchestrator for a two-pass pipeline: lex, parse, build the symbol table, then encode. It runs the stages implemented by Lexer, Parser, SymTableGenerator, and Encoder, collecting errors from whichever stage fails and stopping there. This page documents Asm itself and the types you interact with through it, not the internals of the other four classes. Included as #include <lc3kit/asm>. 

// minimal assemble-and-dump
lc3kit::lasm::Asm asmr;

if (asmr.assemble(source_stream)) {
    asmr.dump(obj_out);
} else {
    // walk asmr.errors(), each has a type and a tpos
}

Asm class

Owns one instance each of Lexer, Parser, SymTableGenerator, Encoder as protected members and drives them in sequence.

methodreturnsdescription
set_ext_enabled(bool)voidPropagates lc3kit-ext enable state to the lexer, parser, and encoder.
is_ext_enabled() constbool
ok() constboolTrue when errors() is empty.
errors() constconst errors_t&All errors collected from whichever stage stopped the pipeline.

assemble(source_code)boolRuns the full pipeline over a raw buffer. Resets internal error state first.
assemble(istream&)boolReads the stream fully, then delegates to assemble(source_code).
dump(ostream&) constvoidWrites assembled sections as big-endian .obj bytes. Caller owns the stream.
Reserved keyword. The header installs at lc3kit/asm, but the namespace is lc3kit::lasm, not lc3kit::asm. asm is a C++ reserved word, so the namespace was renamed while the include path was not.
Reusable instance. assemble() clears the internal error list on every call, so the same Asm object can assemble several source files in a row without manual resets.
Errors are single-stage. The pipeline stops at the first stage that reports errors, so errors() only ever holds output from one stage at a time: lexer errors, or parser errors, or symbol table errors, or encoder errors, never a mix.
Extension immediates. lc3kit-ext instructions (SHL, SHR, MUL, DIV) take a 3-bit immediate, not the 5-bit field used by core ADD/AND.
dump() ordering. Sections are written in the order the encoder produced them, which follows source order, not ascending address order.
